# チーム稼働時間の管理

[旬間 (SHUNKAN) チーム 稼働可能時間（Google スプレッドシート）](https://docs.google.com/spreadsheets/d/1uhg_GI92FFj_DdaErCdueafH2qLMVaCgaeaB0pGFlc4/edit?usp=sharing)

## オンライン版を使う

チームの稼働可能時間は、Googleスプレッドシート **「旬間 (SHUNKAN) チーム 稼働可能時間」** を正本として管理します。Googleスプレッドシートなら、6人が同時に更新でき、合計時間は自動で反映されます。

リーダーは上の Google スプレッドシートの共有設定を確認し、メンバー6人を編集者として追加します。URLをチームチャットに固定し、共有範囲はチームメンバーだけにしてください。

入力範囲には「数値・0〜12」の入力規則を設定し、誤った値を入れにくくします。合計列・日別合計行・チーム総稼働時間・日付・氏名欄は保護範囲にし、編集権限をリーダーに限定します。

## メンバーが入力すること

自分の行の各日に、開発へ使える時間を数字で入力します。

- 1日空いている: `8`
- 半日: `4`
- 夜だけ: `3`
- 稼働できない: `0`
- 固定の予定、8月21日の中間チェック、8月28日の審査発表に参加できない場合: 備考欄にも記入

入力欄は0〜12時間に制限されています。誤った値を入れにくくし、集計のずれを防ぎます。

## リーダーが見る場所

### 各メンバーの行

- 分かること：個人がいつ・何時間動けるか
- 使い方：担当を依頼する前に確認する

### `合計` 列

- 分かること：メンバーごとの期間合計
- 使い方：負担が偏っていないかを見る

### `日別合計` 行

- 分かること：日ごとのチーム総時間
- 使い方：実装・テスト・発表準備の日に人手が足りるかを見る

### 上部のチーム総稼働時間

- 分かること：全期間の見込み時間
- 使い方：Must機能の量が現実的か判断する

## 毎日の使い方

1. 全員がキックオフ終了までに、全期間の稼働予定を自分の行へ入力する。
2. 各メンバーが予定変更時に自分の行を更新する。変更がない場合も、朝の確認までにチャットで「変更なし」と伝える。
3. 進行担当が朝の短い確認前に、当日の稼働人数・日別合計・困りごとを確認する。
4. 時間が少ない日は、Must機能に関係するタスクを優先し、Should/Couldは後ろへ送る。
5. 8月20日の講師相談、8月21日の中間チェック、8月28日の審査発表は、参加可否を備考で再確認する。

## GitHubとの役割分担

- 稼働時間・急な予定変更: Googleスプレッドシートで更新する。
- 企画、仕様、開発手順: このリポジトリの `docs` で管理する。
- 実装タスクの状態: GitHub Issues と Pull Request で管理する。

稼働時間の予定はGitにコミットしません。予定変更をすぐ反映できるGoogleスプレッドシートを正本にすることで、コードレビューと予定管理を混ぜずに運用できます。
