# プロダクト方針：SHUNKAN

## ひとことで

SHUNKAN は、夏などの「限られた季節」にやりたいことをタスクとして登録し、残り日数と達成状況を見ながら、その季節を自分らしく楽しむためのアプリです。

夏休みの終わりに「何をしたんだろう」と思うのではなく、日々の小さな行動を残して、夏を楽しめた実感をつくります。

この方向性は TechJam TOKYO 2026 のテーマ「季節のイベント／レジャー／グルメ／自然・癒しをより快適にするサービス」に対応します。詳細な根拠は [05-techjam-tokyo2026-requirements.md](05-techjam-tokyo2026-requirements.md) にまとめています。

## 解決したいこと

- 夏にやりたいことは思い付くが、日常に流されて忘れてしまう。
- 大きな目標だけだと手を付けにくく、達成感を得にくい。
- 残り時間と、すでに楽しめたことをひと目で振り返りたい。

## 想定する利用者

夏をもっと充実させたい学生・若者。スマートフォンで短時間に使うことを主に想定します。

## 利用イメージ

1. 利用者は「夏の終わり」を設定する、または用意された夏の期間を選ぶ。
2. 「花火を見る」「かき氷を食べる」「友達と海へ行く」など、夏に達成したいことを登録する。
3. 実行できたらタスクを完了にし、必要なら短い思い出メモや写真を残す。
4. ホーム画面で「夏の終わりまであと○日」「達成○/○件」「楽しめた度」を見る。
5. 夏の終わりには、達成したことの一覧を振り返る。

## 最初に作る機能（MVP）

審査発表までには、次を確実に動く状態にします。

### Must：季節カウントダウン

- できること：夏の終わりまでの残り日数を見る
- 目的：残り時間を意識して、やりたいことを後回しにしにくくする

### Must：夏タスクの登録

- できること：やりたいことをタイトル・カテゴリ・期限付きで追加する
- 目的：思い付いた夏の予定や目標を忘れないようにする

### Must：タスク一覧・完了

- できること：未完了と完了を見分け、完了に切り替える
- 目的：次にやることと、すでに楽しめたことを分けて見られるようにする

### Must：達成状況

- できること：完了数・進捗率・完了したタスク一覧を見る
- 目的：夏を楽しめた実感を分かりやすくする
- 範囲：Mustでは、完了したタスク自体を「思い出」として振り返る。思い出メモは含めない。

### Should：思い出メモ

- できること：完了したタスクに一言メモを残す
- 目的：あとで振り返ったときに、その時の気持ちを思い出せるようにする

### Could：写真

- できること：思い出に写真を添える
- 目的：体験をより具体的に振り返れるようにする

### Could：季節の切替

- できること：夏以外の季節も選べるようにする
- 目的：秋・冬・春にも同じ体験を広げられるようにする

`Must` が完成してから `Should` と `Could` に進みます。ログイン、SNS 共有、通知などは今回のMVPには含めません。

## 主要画面

### ホーム

- 目的：今の夏の状態を知る
- 表示するもの：残り日数、進捗率、完了数、次にやるタスク

### タスク一覧

- 目的：やりたいことを管理する
- 表示するもの：未完了/完了タブ、カテゴリ、各タスク

### タスク作成・編集

- 目的：やりたいことを登録する
- 表示するもの：タイトル、カテゴリ、期限、メモ（Should）

### 夏の振り返り

- 目的：夏を楽しめた実感を得る
- 表示するもの：達成一覧、達成数、思い出メモ（Should）

## MVPの期間・期限ルール

- MVPでは夏の終了日を **2026年8月31日（日本時間）** に固定し、利用者による変更や季節の選択はしない。
- 残り日数は、8月31日までの日数を表示する。9月1日以降は `0日` と「夏は終了しました」を表示する。
- タスクの期限は必須とし、2026年8月31日以前の日付だけを登録できる。
- 夏の終了日の変更、夏以外の季節、終了後のタスク登録は Could の「季節の切替」を実装する際に改めて設計する。

## 成功の基準

- 初めて使う人が、1分以内に夏のやりたいことを1件登録できる。
- ホーム画面で、残り日数と達成状況が迷わず読める。
- タスクを完了にした直後、夏を楽しめたことが視覚的に分かる。

## 今回の判断

- バックエンドは Django を採用します。
- フロントエンドは、まず Django Templates と HTML / CSS で作ります。
- Tailwind CSS は、導入によって画面制作が速くなるとチームで判断した場合にのみ採用します。導入前に担当者が相談し、スタイルを混在させないことを決めます。
