# チーム稼働時間の管理

## オンライン版を使う

チームの稼働可能時間は、Googleスプレッドシート **「SHUNKAN チーム 稼働可能時間」** を正本として管理します。Googleスプレッドシートなら、6人が同時に更新でき、合計時間は自動で反映されます。

リーダーは作成済みのシートをメンバー6人に編集者として共有し、URLをチームチャットに固定してください。共有範囲はチームメンバーだけにします。

## メンバーが入力すること

自分の行の各日に、開発へ使える時間を数字で入力します。

- 1日空いている: `8`
- 半日: `4`
- 夜だけ: `3`
- 稼働できない: `0`
- 固定の予定、8月21日の中間チェック、8月28日の審査発表に参加できない場合: 備考欄にも記入

入力欄は0〜12時間に制限されています。誤った値を入れにくくし、集計のずれを防ぎます。

## リーダーが見る場所

| 場所 | 分かること | 使い方 |
| --- | --- | --- |
| 各メンバーの行 | 個人がいつ・何時間動けるか | 担当を依頼する前に確認する |
| `合計` 列 | メンバーごとの期間合計 | 負担が偏っていないかを見る |
| `日別合計` 行 | 日ごとのチーム総時間 | 実装・テスト・発表準備の日に人手が足りるかを見る |
| 上部のチーム総稼働時間 | 全期間の見込み時間 | Must機能の量が現実的か判断する |

## 毎日の使い方

1. 各メンバーが予定変更時に自分の行を更新する。
2. 朝の短い確認で、当日の稼働人数・日別合計・困りごとを確認する。
3. 時間が少ない日は、Must機能に関係するタスクを優先し、Should/Couldは後ろへ送る。
4. 8月20日の講師相談、8月21日の中間チェック、8月28日の審査発表は、参加可否を備考で再確認する。

## 日付の扱い

提供されたCSVは未入力テンプレートで、曜日・フェーズの並びが2026年の公式スケジュールと一致していませんでした。オンライン版では、TechJam配布資料に合わせて次のように修正しています。

- 8月18日（火）: キックオフ
- 8月20日（木）: 吉永講師への相談
- 8月21日（金）: 中間チェック
- 8月23日（日）: Must機能の完成を目安
- 8月28日（金）: 審査発表

公式日程の根拠は [05-techjam-tokyo2026-requirements.md](05-techjam-tokyo2026-requirements.md) と原本PDFです。

## GitHubとの役割分担

- 稼働時間・急な予定変更: Googleスプレッドシートで更新する。
- 企画、仕様、開発手順: このリポジトリの `docs` で管理する。
- 実装タスクの状態: GitHub Issues と Pull Request で管理する。

稼働時間をGitにコミットし直す運用にはしません。予定変更をすぐ反映できるGoogleスプレッドシートを正本にすることで、コードレビューと予定管理を混ぜずに運用できます。
