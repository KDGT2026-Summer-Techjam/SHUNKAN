# Issue・GitHub Actions 運用

## Issueの担当割り振り

開発タスクはGitHub Issue #2〜#13に登録しています。担当・期限・完了条件は [04-roadmap-and-tasks.md](04-roadmap-and-tasks.md) と各Issueで同じ内容を確認できます。

GitHubの招待を承認するまでは、Issueの担当者欄に設定できません。承認前でも、Issue本文の `@メンション` で担当予定を確認できます。承認後、PMは各Issueの担当者欄にも同じメンバーを設定します。

## 自動メンション

`.github/workflows/issue-assignment-mention.yml` は、Issueの担当者が変更されたときに、その担当者へコメントで `@メンション` します。

- Issueへの割当イベントは、GitHubの仕様によりデフォルトブランチ（現在は `main`）上のワークフローで実行されます。
- `dev` では、push・`dev` 宛てPR・手動実行でワークフロー設定を確認できます。
- `dev` 上で手動実行する場合は、Issue番号とGitHubユーザー名を入力すると、同じメンションコメントを試せます。

Issueへの自動メンションを有効にするには、このワークフローを最終的に `main` へ取り込む必要があります。`main` へのマージはリポジトリ管理者が行います。

## 役割変更時

@ayato-hはバックエンドを主担当としつつ、フロントエンド支援へ転向できます。転向する場合は、PMが次を行います。

1. 影響するIssueで新しい担当者を設定する。
2. Issueコメントに、変更理由と引き継ぐ内容を書く。
3. 自動メンションで新担当者へ通知されることを確認する。
