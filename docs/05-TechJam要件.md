# TechJam TOKYO 2026：配布資料に基づく要件

この文書は、チームに共有された [TECHJAM TOKYO 2026 配布資料](reference/TECHJAM-TOKYO2026.pdf) の内容を、旬間 (SHUNKAN) の開発で使いやすい形に整理したものです。正式な案内は原本PDFを優先します。

## プロジェクトの目的

TechJamでは、Git・設計・レビューを含む実務に近いチーム開発を短期集中で経験し、企画から実装までをやり切り、仲間と成長することが目的です。

旬間 (SHUNKAN) では「動くものを完成させる」ことと、Issue・PR・レビューを残しながらチームで進めることの両方を成果にします。

## テーマとの対応

### 季節のイベント

花火、祭り、旅行など、夏にしたい体験をタスクにします。

### レジャー・グルメ

海、かき氷、カフェ巡りなどをカテゴリとして記録できるようにします。

### 自然・癒し

自然に触れる、休む、散歩するなどの過ごし方も登録できるようにします。

### より快適にするサービス

残り日数と達成状況で、やりたいことを実行しやすくします。

## チーム開発の5つのルール

1. `main` へ直接 Push しない。作業ブランチから `dev` 宛てに PR を出して取り込む。
2. 作業はGitHub Issueで管理し、「誰が・何を・どこまで」を見える化する。
3. 小さく作って早く統合する。最終日にまとめて結合しない。
4. 分からない状態を放置しない。15〜30分調べても進まなければ共有・相談する。
5. 機能を増やしすぎない。Must → Should → Couldの順で、まずMVPを完成させる。

旬間 (SHUNKAN) では、これを [03-GitHub運用手順.md](03-GitHub運用手順.md) と [04-ロードマップとタスク.md](04-ロードマップとタスク.md) の具体的な運用に落とし込んでいます。

## 連絡と安全のルール

- 稼働・欠席・進捗遅れ・業務質問は、まずチームリーダーに伝えます。
- リーダーは必要に応じて運営スタッフ、講師、他チームとの窓口になります。
- 夏場の長時間作業では体調管理を優先し、無理をしないこともチームへの貢献とします。
- スキル差や意見の違いを尊重し、攻撃的な言動をしません。
