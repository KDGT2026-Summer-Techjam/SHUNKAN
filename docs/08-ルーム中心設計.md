# ルーム中心の設計

## プロダクトの認識

旬間は、個人用の期限付きルーム管理アプリです。

- 2026 夏は最初に用意するルームの1つです。
- TechJam 2026 は、2026年8月28日18:00（日本時間）を終了日時にしたデモ用ルームです。
- 文化祭まで、沖縄旅行までのように、利用者は目的ごとにルームを作れます。
- ルームは共有チャットではありません。作成者だけが見られる、期間・タスク・記録をまとめる箱です。
- ルームごとに開始日時・終了日時を持ち、カウントダウン、進捗、アルバムを独立して表示します。

    ログインした利用者
    ├─ 2026 夏
    │  ├─ 花火 / グルメ などのカテゴリ
    │  ├─ タスク
    │  └─ 瞬間ログと写真
    └─ TechJam 2026
       ├─ 準備 などのカテゴリ
       ├─ タスク
       └─ 瞬間ログと写真

## データの関係

    User
    └─ Room
       ├─ Category
       ├─ Task
       └─ MomentLog
            └─ Photo

| データ | 役割 | 例 |
| --- | --- | --- |
| Room | 期限とテーマをまとめる | 2026 夏、文化祭まで |
| Category | ルーム内での分類 | 花火、グルメ、準備 |
| Task | これからやりたいこと | 花火を見る |
| MomentLog | 実際に起きたこと・気持ち | 最後の一発がすごかった |
| Photo | 瞬間ログに添える写真とひとこと | 花火の写真、写真へのコメント |

完了タスクや進捗率は別テーブルにしない。Task の完了状態と完了日時から、完了数と進捗率を計算する。

## 写真と写真へのひとこと

写真は Task へ直接ぶら下げず、MomentLog に紐づける。

    タスク「花火を見る」を完了
      ↓
    任意で「写真・ひとことを残す」を選ぶ
      ↓
    そのタスクに紐づく MomentLog を作る
      ↓
    MomentLog に Photo を0枚以上添える
      ↓
    Photo ごとに短い caption を残す
      ↓
    アルバムに時系列で表示する

- MomentLog の本文は、出来事や気持ちを書く。
- Photo の caption は、写真そのものを見返すための一言を書く。
- caption は他ユーザーとの会話やコメント欄ではない。作成者だけが編集できる。

画像本体はDBではなくストレージに保存する。開発中はDjangoの media フォルダ、公開時は画像ストレージを使う。EXIFの撮影日時は将来機能とし、GPS・端末名などの生メタデータは明示的な同意なしに保存しない。

## 終了後の振り返り

ルームは終了したら基本的に閲覧専用です。Mustが完成し、時間が残った場合だけAdditionalとして次を追加します。

    ルーム開催中
      → タスク追加・完了・通常ログ・写真投稿ができる

    ルーム終了後から7日間
      → 「この期間を振り返る」ログだけ投稿できる
      → 新しいタスクや通常ログは追加できない

    振り返り期限後
      → 閲覧専用

振り返りログは MomentLog の entry_type を reflection にして通常ログと区別する。投稿期限は Room の reflection_deadline_at で管理する。

## 画面遷移

    登録・ログイン
      ↓
    ルーム一覧 ──→ ルームを作る
      ↓
    ルームホーム
      ├─→ タスク一覧 ──→ タスク追加・編集 ──→ タスク一覧
      ├─→ 今を残す ──→ アルバム
      └─→ アルバム

## 技術方針

| 領域 | 方針 | 理由 |
| --- | --- | --- |
| バックエンド | Django | 認証、フォーム、ORM、管理画面を一つで扱える |
| 認証 | Django標準Auth | 独自のパスワード実装を避ける |
| 開発DB | PostgreSQL | ログイン後の複数利用者・将来の公開を見据える |
| 画像処理 | Pillow | 画像の確認、将来のEXIF撮影日時取得に使う |
| フロント | Django Templates、HTML、CSS、少量JavaScript | デモまでの開発量を抑え、Figmaの見た目を統一する |
| CSS | デザイントークン＋共通CSS | Tailwindの新規学習・ビルド設定を増やさない |

PostgreSQLは各自のローカル環境で起動する。接続情報は .env に置き、パスワードや接続URLをGitへコミットしない。

## ブランチを分ける順序

前のPRがdevに入ったら、次の担当は最新のdevから作業を始める。

| 順序 | ブランチ例 | 内容 | 依存 |
| --- | --- | --- | --- |
| 1 | feature/room-product-docs | この設計資料と要件更新 | なし |
| 2 | feature/postgres-setup | PostgreSQL、.env.example、初心者向けセットアップ手順 | 1 |
| 3 | feature/room-models | Room、Category、Task、MomentLog、Photoとmigration | 2 |
| 4 | feature/authentication | 登録、ログイン、ログアウト、所有者チェック | 3 |
| 5 | feature/task-and-log-crud | タスク、瞬間ログ、完了、進捗、アルバム | 3、4 |
| 6 | feature/photo-upload | 写真アップロード、MomentLogへの紐付け、アルバム表示 | 3、4、5 |
| 7 | feature/photo-metadata | EXIF撮影日時の取得・確認・表示 | 6 |
| 8 | feature/figma-ui | Figmaに合わせた共通CSSとスマホ画面 | 4、5、6 |

写真のEXIF日時は、写真アップロードが安定してから別PRで実装する。GPS位置情報は今回の対象にしない。
