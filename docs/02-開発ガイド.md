# 開発手順書

## はじめに

このプロジェクトは、Django をバックエンド、Django Templates を使った HTML / CSS をフロントエンドの基本構成にします。まず「画面を表示する → データを保存する → 画面に反映する」の順で、ひとつずつ小さく完成させます。

役割を分け、変更を小さくし、動作を確認してから Pull Request（PR）で共有します。実装の詳細は、このプロジェクトの構成ができた後にチームで統一します。

> **迷ったら:** まず自分のIssueの「完了条件」を読みます。15〜30分調べても進まなければ、エラー内容・試したこと・期待した結果をPMへ共有してください。

## 初心者向け：作業を始める前の流れ

1. GitHub の Issue または担当表で、自分のタスクを確認します。
2. `dev` を最新にしてから、自分専用の作業ブランチを作ります。
3. 変更は「1つの目的」に絞ります。例：タスク追加フォームだけを作る。
4. ブラウザで実際に画面を開き、期待した通りに動くか確認します。
5. PR を `dev` 宛てに作り、何を確認したかを書きます。
6. レビューで直す点があれば修正し、承認後に `dev` へ取り込みます。

15〜30分調べても進まない場合は、ひとりで抱え込まずリーダーへ共有・相談します。

Git の具体的な操作は [03-GitHub運用手順.md](03-GitHub運用手順.md) を参照してください。

## 開発環境を準備する

T-01 の土台が `dev` に取り込まれた後、リポジトリのルートで次を実行します。

```bash
python3 -m venv .venv
source .venv/bin/activate
cp .env.example .env
python -m pip install -r requirements.txt
python manage.py migrate
python manage.py check
python manage.py test
python manage.py runserver
```

ブラウザで `http://127.0.0.1:8000/` を開き、`旬間 (SHUNKAN)` と表示されることを確認します。`requirements.txt` または `manage.py` がない場合は、土台が未完成か、別の実行手順が必要です。自分でファイルを作らず、T-01 の担当者またはリーダーへ確認してください。

公開環境では `.env` に `DJANGO_DEBUG=false`、ランダムな `DJANGO_SECRET_KEY`、公開先の `DJANGO_ALLOWED_HOSTS` を設定します。`.env` はGit管理しません。

## 実装の順番

### 1. 土台

- 目的：Django を起動し、共通レイアウトを表示する
- ゴール：開発環境でトップページが開く

### 2. 見た目

- 目的：ホーム・一覧・登録画面の静的な見た目を作る
- ゴール：スマホ幅でも内容を読める

### 3. データ

- 目的：夏タスクを保存できるようにする
- ゴール：登録したタスクが一覧に残る

### 4. 操作

- 目的：完了切替・進捗表示をつなぐ
- ゴール：完了数と進捗率が変わる

### 5. 仕上げ

- 目的：文言、余白、エラー表示を整える
- ゴール：初見の人が一連の操作をできる

## 画面づくりのルール

- 最初はスマートフォン幅を基準にします。重要な情報は上から「残り日数 → 進捗 → 次のタスク」の順に置きます。
- 色だけで完了・未完了を区別せず、ラベルやアイコンも使います。
- ボタンの文言は「追加」「完了にする」のように、押した結果が分かる言葉にします。
- 画面に仮データを置く場合は、PR の説明に「仮」と明記します。
- CSS は既存の共通ルールを優先し、同じ見た目をコピーして増やさないようにします。

## Django の役割分担（予定）

実装開始時に、次のような構成を目安にします。実際のアプリ名やフォルダ名は、土台担当が決めたものに合わせます。

### `models.py`

タスクなど、保存するデータの形を定義します。

### `views.py`

画面を開く・登録する・完了にする処理を書きます。

### `urls.py`

URL と画面処理をつなぎます。

### `templates/`

HTML の画面を置きます。

### `static/`

CSS、画像、JavaScript を置きます。

### `tests.py`

登録や完了切替などの動作を確認します。

## 実装前・PR前の確認

### 実装前

- 自分のタスクの完了条件を一文で説明できる。
- 似た画面やコンポーネントが既にないか確認した。
- 変更するファイルが担当範囲に収まっている。

### PR前

- 開発サーバーで対象画面を開いた。
- 入力・表示・完了切替など、自分が触った流れを確認した。
- 画面がスマートフォン幅で崩れていない。
- 不要なファイル、秘密情報、個人情報を追加していない。
- PR に「変更内容」「確認方法」「まだ残ること」を書いた。

## 困ったとき

- エラーを消そうとして、関係ないファイルを大きく書き換えないでください。
- 分からない場合は、エラー画面の文章・自分がした操作・期待した結果を担当リーダーに共有します。
- 他の人の作業と重なりそうなら、実装前に担当表またはチャットで相談します。

## PostgreSQLをローカルで使う

このプロジェクトでは、開発環境のデータベースに PostgreSQL を使用します。

初めてセットアップする場合は、以下の手順で PostgreSQL の起動、`.env` の設定、データベース作成、Django の migration を行います。

### 1. PostgreSQLを起動する

macOSでHomebrewを使って PostgreSQL 15 をインストールしている場合は、次を実行します。

```bash
brew services start postgresql@15
```

PostgreSQLが起動しているか確認する場合は、次を実行します。

```bash
brew services list
```

`postgresql@15` が `started` になっていれば起動しています。

### 2. `.env` を作成する

プロジェクトのルートディレクトリで、`.env.example` をコピーします。

```bash
cp .env.example .env
```

`.env` を開き、ローカルPostgreSQLの接続情報を設定します。

```env
POSTGRES_DB=shunkan
POSTGRES_USER=postgres
POSTGRES_PASSWORD=自分で設定したパスワード
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
```

`POSTGRES_PASSWORD` には、自分のローカルPostgreSQLユーザーに設定したパスワードを入力してください。

`.env.example` には実際のパスワードなどの秘密情報を記載しません。

また、`.env` はGitにコミットしないでください。

### 3. PostgreSQLにデータベースを作成する

PostgreSQLに接続します。

```bash
psql -U postgres -d postgres
```

パスワードを求められたら、PostgreSQLの `postgres` ユーザーに設定したパスワードを入力します。

PostgreSQLに接続できたら、以下を実行してデータベースを作成します。

```sql
CREATE DATABASE shunkan;
```

データベースがすでに存在する場合は、この手順を飛ばしてください。

作成後、PostgreSQLを終了します。

```sql
\q
```

### 4. Djangoのマイグレーションを実行する

仮想環境を有効にした状態で、プロジェクトのルートディレクトリから以下を実行します。

```bash
python manage.py migrate
```

各マイグレーションが `OK` と表示されれば、DjangoとPostgreSQLの接続は成功しています。

### 5. Djangoの設定を確認する

以下を実行します。

```bash
python manage.py check
```

次のように表示されれば問題ありません。

```text
System check identified no issues (0 silenced).
```

### 6. 開発サーバーを起動する

以下を実行します。

```bash
python manage.py runserver
```

ブラウザで `http://127.0.0.1:8000/` を開き、アプリが表示されることを確認します。

### 7. PostgreSQLを停止する

作業終了後、PostgreSQLを停止する場合は以下を実行します。

```bash
brew services stop postgresql@15
```

PostgreSQLを使用しない場合に停止してください。
