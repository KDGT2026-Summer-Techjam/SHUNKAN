# 開発手順書

## はじめに

旬間（SHUNKAN）は、Djangoをバックエンド、Django Templatesを使ったHTML / CSSをフロントエンドの基本構成にします。開発・テストのデータベースはPostgreSQL必須であり、SQLiteフォールバックは採用しません。

> **迷ったら:** まず自分のGitHub Issueの完了条件を読みます。15〜30分調べても進まなければ、エラー内容・試したこと・期待した結果をPMへ共有してください。

## 初心者向け：作業を始める前の流れ

1. GitHub Issueで自分のタスク、依存関係、Assigneesを確認する。
2. `dev`を最新にしてから、自分専用の作業ブランチを作る。
3. 変更は1つの目的に絞る。
4. 対象の動作とテストを確認する。
5. PRを`dev`宛てに作り、変更内容・確認方法・未対応のことを書く。

Gitの具体的な操作は[03-GitHub運用手順.md](03-GitHub運用手順.md)を参照してください。

## PostgreSQL必須のローカル開発環境

`requirements.txt`にはPostgreSQLへ接続するためのドライバが含まれる前提です。ドライバの具体的なパッケージ名は、`requirements.txt`の実際の記載を確認してください。

### 1. 仮想環境を作成して有効化する

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### 2. PostgreSQLを起動する

macOSでHomebrewを使ってPostgreSQL 15をインストールしている場合は、次を実行します。

```bash
brew services start postgresql@15
```

起動状況は次で確認できます。

```bash
brew services list
```

### 3. `.env`を作成して接続情報を設定する

プロジェクトのルートディレクトリで`.env.example`をコピーします。

```bash
cp .env.example .env
```

`.env`を開き、ローカルPostgreSQLの接続情報を設定します。

```env
POSTGRES_DB=shunkan
POSTGRES_USER=postgres
POSTGRES_PASSWORD=自分で設定したパスワード
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
```

`.env.example`には実際のパスワードなどの秘密情報を記載しません。`.env`はGit管理しません。

### 4. PostgreSQLにデータベースを作成する

```bash
psql -U postgres -d postgres
```

PostgreSQLに接続できたら、以下を実行します。データベースがすでに存在する場合はこの手順を飛ばします。

```sql
CREATE DATABASE shunkan;
```

終了するには次を実行します。

```sql
\q
```

### 5. migration、設定確認、テストを実行する

```bash
python manage.py migrate
python manage.py check
python manage.py test
```

`migrate`、`check`、`test`はいずれもPostgreSQLへ接続できる状態で実行します。SQLiteでの動作確認は完了条件にしません。

### 6. 必要ならデモデータを投入する

migration完了後、画面確認用データが必要な場合だけ実行します。

```bash
python manage.py seed_demo
```

`seed_demo`は、2026 夏（2026-08-31 23:59:59 JSTまで）とTechJam 2026（2026-08-28 18:00:00 JSTまで）のデモデータを作成します。ログイン用パスワードを設定・提供するコマンドではありません。

### 7. 開発サーバーを起動する

```bash
python manage.py runserver
```

ブラウザで`http://127.0.0.1:8000/`を開きます。

### 8. PostgreSQLを停止する

作業を終えて停止したい場合は、以下を実行します。

```bash
brew services stop postgresql@15
```

## ファイルの扱い

- `.env`、`media/`、実際にアップロードした画像はGit管理しない。
- `static/`はアプリで配信するCSS・共通画像・JavaScript、`media/`は利用者がアップロードした写真の保存先として扱う。
- 写真はJPEG / PNG / WebP形式、1枚5MB以下、MomentLog 1件あたり最大3枚とする。

## 実装前・PR前の確認

### 実装前

- 自分のIssueの完了条件と依存関係を説明できる。
- 変更するファイルが担当範囲に収まっている。
- Room状態・所有者・期間の制約に関わる場合、関連Issueと既存方針を確認した。

### PR前

- 対象画面・入力・エラー時の流れを確認した。
- `python manage.py check`と`python manage.py test`をPostgreSQL環境で実行した。
- スマートフォン幅で主要な画面が崩れていない。
- 秘密情報、`media/`、実際のアップロード画像、不要な生成物を追加していない。
- PRに変更内容、確認方法、未対応のことを書いた。
